# Руслан Эхтибаров — инженер-конструктор

Персональное инженерное портфолио. Next.js App Router, React, TypeScript, Tailwind CSS 4 и авторская SVG-графика. Полностью статический сайт: сервер, БД и ключи API не требуются.

Адрес GitHub Pages: **https://zubarevlab.ru/reengineering/**

## Локальный запуск

Требуется Node.js 22 или новее (проверено на Node 24) и npm.

```sh
npm ci
npm run dev
```

Откройте `http://127.0.0.1:3000`. Шрифты размещены локально через Fontsource; при просмотре браузер не обращается к Google Fonts. Фото оптимизировано в WebP, лицо и внешность не изменены.

Проверка готовой production-версии:

```sh
npm run build:pages
npm start
```

Локальный сервер перенаправит на `http://127.0.0.1:3000/reengineering/`. Он показывает файлы из `out/`, включая префикс GitHub Pages. Команда `npm run build` создаёт отдельную сборку для размещения в корне домена.

## Проверки

```sh
npm run lint
npm run typecheck
npm run build:pages
npm run test:e2e
```

На Windows тесты используют установленный Google Chrome. Для Linux/macOS без Chrome установите Chromium (`npx playwright install chromium`) и запустите с `CI=1`. В GitHub Actions браузер устанавливается автоматически.

Playwright проверяет размеры 320, 390, 768, 1024, 1440 и 1920 px, отсутствие горизонтального скролла, загрузку фото, axe WCAG A/AA, карьерные вкладки, клавиатуру, мобильное меню, аккордеон, все этапы инженерной схемы, PDF, обработку отсутствующего PDF, буфер обмена, контакты, метаданные и печать. Скриншоты и отчёт сохраняются локально в `.qa/`, диагностические файлы — в `test-results/`; они не публикуются.

## GitHub Pages

1. Репозиторий `zubarevmarketplace/reengineering` должен быть публичным для бесплатного GitHub Pages.
2. В Settings → Pages выберите Source → GitHub Actions.
3. Push в `main` запускает `.github/workflows/pages.yml`: lint, TypeScript, production build, браузерные проверки, затем публикацию `out/`.
4. Адрес: `https://zubarevlab.ru/reengineering/`.

`scripts/build-pages.mjs` задаёт `NEXT_PUBLIC_BASE_PATH=/reengineering` и конечный URL. Пути изображения, резюме, favicon, Open Graph и ресурсов Next.js учитывают подкаталог. При переименовании репозитория измените значения в этом скрипте либо задайте переменные окружения в workflow.

## Vercel или свой домен

1. Импортируйте репозиторий в Vercel.
2. Framework Preset: Next.js; Build Command: `npm run build`.
3. Задайте `NEXT_PUBLIC_SITE_URL=https://ВАШ-ДОМЕН/` с завершающим слешем. Не задавайте `NEXT_PUBLIC_BASE_PATH` для сайта в корне домена.
4. Запустите Deploy. `output: "export"` отдаёт полностью статический сайт. Для другого статического хостинга загрузите содержимое `out/`.

Без `NEXT_PUBLIC_SITE_URL` сборка намеренно отдаёт `noindex` и запрещающий `robots.txt`, а sitemap остаётся пустым. Это защищает промежуточные версии от индексации. В GitHub Pages-сборке URL настроен: canonical, Open Graph, Person JSON-LD, robots и sitemap генерируются для реального адреса.

## Редактирование содержания

Основные факты, контакты, инструменты, образование и пять должностей находятся в `src/data/resume.ts`. Вводный текст разделов и последовательность секций — в `src/app/page.tsx`. Цвета, типографика и адаптивные правила — в `src/app/globals.css`. Изменение контактов в data-файле обновляет кнопки и структурированные данные.

Даты переходов между должностями неизвестны и намеренно не указаны. Высшее образование обозначено как продолжающееся. Стаж задан датой начала работы, без быстро устаревающих чисел. SVG-корпус — условная демонстрационная схема, а не реальный проект кандидата. Количественные результаты и отзывы не добавлялись.

## Материалы и публичность

Фотография и профессиональные сведения предоставлены заказчиком. Заказчик подтвердил согласие кандидата на публичное размещение фотографии, телефона, почты и резюме. Исходный PDF не входит в репозиторий: публичная производная версия удаляет дату рождения, возраст и устаревшие длительности стажа, сохраняя профессиональное содержание. Удаление выполнено redaction-операциями с очисткой PDF, а не наложением прямоугольников поверх текста. Оригиналы не изменены.

Для повторной подготовки материалов на Windows: установите Pillow и PyMuPDF в отдельное Python-окружение, затем выполните `python scripts/prepare-assets.py --source-dir ПАПКА_С_ИСХОДНИКАМИ`. Скрипт адаптирован под конкретный двухстраничный исходный PDF; при замене его вёрстки требуется пересмотреть координаты удаления. Для обычного обновления сайта Python не нужен: все готовые ресурсы включены.

Версия для печати доступна через стандартную команду браузера «Печать»: раскрывает все должности, убирает навигацию и интерактивные элементы. Почта отправляется через настроенный почтовый клиент пользователя, телефон открывает приложение звонков. Копирование работает в защищённом HTTPS-контексте и localhost; при запрете буфера обмена отображается инструкция.

## Производительность и сопровождение

Клиентский JS используется только для навигации, вкладок, контактов и PDF. Нет аналитики, трекеров, внешних форм или тяжёлой 3D-библиотеки. Включены локальные шрифты с `font-display: swap`, заданные размеры фото, `prefers-reduced-motion`, фокус с клавиатуры и семантическая разметка. Lighthouse и реальные Core Web Vitals зависят от устройства и сети; результаты не подменяются обещанием фиксированного балла.

Зависимости зафиксированы в `package.json` и `package-lock.json`. На момент подготовки `npm audit` сообщает об умеренном предупреждении в цепочке `minimatch`/ESLint (инструменты разработки); критических и высоких проблем нет. Не используйте `npm audit fix --force`: предложенный откат ESLint несовместим с современным Next.js. Production-зависимости проверяются отдельно командой `npm audit --omit=dev`.

Официальные инструкции: [Next.js static export](https://nextjs.org/docs/app/guides/static-exports), [GitHub Pages custom workflows](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).
